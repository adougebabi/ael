4. 只建立一张小范围表：当前代码/测试 → 保留 / 修改 / 退出活动路径 → 对应新验收。每项必须有实际落点，不写新的长篇候选架构研究。

**本步收口：** 不再存在同时要求“CLI 只通信”和“必须管理全部后代进程”的活动规范；WORKLOG 当前仍为 V2-12。

## R12.2 打通薄客户端路径，退出远程进程托管

1. 复用注册、身份、claim、context、进度、候选、附件、submit、receipt、next-work API；现有 server/CLI 权限、幂等和版本规则不另建一套。
2. CLI 不启动 Codex、编译、测试、Git push、Docker，不创建受管执行副本，也不自动回写原 checkout。
3. 仅通信可保留可选续租/上传助手；无需常驻进程也应能用 CLI 完成一条任务。
4. `RUNNER_ISOLATION_REQUIRED` 不再全局封住薄客户端操作。把实际保留的身份/项目/Attempt/版本/证据校验逐一保留。旧的未验证远程托管入口明确停用，不能通过删总门禁使它隐式恢复执行。
5. 对已有稳定 Local Managed 能力只做兼容回归，既不让它成为新主路径前置，也不在本项大拆除。

**本步收口：** 外部测试驱动器可以通过正式 CLI 取得工作、上传文件并提交结果；AEL 自身没有启动测试驱动器或其工程子进程。无 Docker 客户端环境正常。

## R12.3 把循环责任交回 Agent，保留工程门禁

1. 更新分发 Skill / 命令引用 / 接入说明：现有 Agent 直接读取任务与规范，自行调用宿主工具执行；每次提交消费 next_action。
2. 当前叶子失败优先修复当前项；已授权且具备能力时接续下一项，不重复询问继续。角色交接则准确结束，不要求原角色调度另一个 Bot。
3. 续租、断线、取消的语义是协作责任管理，不是 OS 停机证明。Agent 应遵守停止请求，Server 拒绝过期有效提交；实际进程状态未知就显示未知。
4. 提交检查结果保留输入候选、方法、执行/判断来源、验收覆盖、报告、截图/日志等；仅摘要、文件存在或退出码不足以完成。
5. 自动归档由已有完成规则决定，不新增直接改终态或人工“全通过”绕过入口。
6. 默认不由 Agent 向中心上传全部代码、HOME、聊天历史或模型凭据；仅选定任务所需资料和证据。

**本步收口：** 外部 Agent 可以在同一会话完成失败修复小 Loop；AEL 可靠记录并判定，缺少外部会话时如实等待。

## R12.4 一次固定范围的正式验证

运行修订后 `tasks/V2-12.md` 的验收集。使用正式构建，不使用 overlay 或仅测试可开启的安全绕过。

测试驱动器从 AEL 之外启动，可以实际写 fixture 文件、运行测试，再调用 CLI；这是明确的集成测试，不是产品 Runner。真实 Agent 可用时另做一次同样方向的 smoke；没有模型环境时保留原任务允许的条件性未验证范围，不把合成驱动器称为真实 Agent。

前置回归集中于 CLI、任务树、next-work、重复失败、父门禁、身份/证据/候选；最后在最终代码上跑相关 race 和全量回归。原有不受本次契约变化影响的失败不能隐藏。

**本步收口：** 固定验收逐条有结果。缺失远程进程强隔离不再算受支持功能的缺陷；身份/授权/旧结果污染/证据串版本仍是硬失败。
