## 实施内容

1. 先按恢复说明核对 V2-00—11 的直接耦合，修订相应 Skill/契约/文案；保留旧状态和回执，只追加必要回归。不为前置盘点重开十二项开发。
2. 复用远程身份、project/checkout/session/attempt 标识和 claim/fence；提供实际可用的 CLI 接入、领取、续租、context、progress、candidate、artifact upload/finalize、result submit、receipt 和 next/next-work。命令名称以现有接口统一，不为本次新增重复别名。
3. 客户端只读选定的本地输入并上报，不启动 Agent、项目检查、Git 发布或 Docker。不建立受管副本，不自动回写原 checkout。服务器同样不执行项目命令。
4. 工作 Skill 指导现有 Agent 自行完成当前责任并提交结构化结果；失败在同一叶子修复，成功后消费 next_action。项目原规则可提供检查标准与工具建议，但 AEL 不接管具体工具进程。
5. 检查报告包含候选、任务/计划/验收版本、方法与来源、实际观察、覆盖及证据。命令执行报告与模型判断/人工结论区分；Agent 不能伪装成独立审批者。上传哈希仅证明内容，不包装成执行真实性证明。
6. 取消/撤权/过期保护 Server 接受的有效结果；通信客户端拒绝继续以旧责任提交，保留待确认数据和准确提示。宿主停工由外部 Agent 按协议响应，不要求客户端杀进程。
7. 将无条件 RUNNER_ISOLATION_REQUIRED 与通信主路径解除耦合；所有真实权限、版本和证据检查继续生效。旧未验收远程托管入口明确不支持，不新增忽略安全开关。
8. 采用外部独立测试驱动器实际修改 fixture 并运行真实命令，再调用打包 CLI；这不是 AEL 启动的执行器。真实 Agent 已可用时另跑 smoke，如实标记覆盖范围。

## 最小手工演练（命令名由实现映射）

外部 Agent 领取叶子并取得上下文 → Agent 自己在隔离 fixture 编辑文件/运行测试 → CLI 上传失败日志并提交失败 → CLI 返回修复责任 → Agent 修复并测试 → CLI 提交通过报告 → Server 计算是否可完成或进入下一责任 → Agent 读取下一动作。
