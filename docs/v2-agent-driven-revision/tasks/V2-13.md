## 实施内容

1. 使用两个独立配置/身份的 CLI，由外部会话分别调用；按能力、项目权限、父计划和 WIP 领取责任，同一单元原子去重。Runner 旧字段可以保留，不要求新增常驻服务。
2. 外部执行者选择独立分支或工作区并提供稳定候选；AEL 核对候选和提交，不替用户 clone/merge/sync 源码。
3. 通信失败使用有界重试与本地待提交记录，同一操作保持幂等键。重连核对 Server 修订与责任，不将旧结果绑定到新任务。
4. lease/fence 过期或撤销后旧写请求拒绝；客户端和 Skill 提示停止旧责任并保留现场。不能由 API 回执声称杀死了外部进程，也不能自动接管未知的同一可写工作区。
5. 责任交接恢复区分已确认停止、未知旧工作区和明确新工作区；旧结果可按受控诊断语义保留，不参与当前门禁。
6. Server 重启后依据持久状态恢复，重复回执查询不产生新副作用；外部部署结果未知时只核查既有运行，不自行重做发布。

## 边界

不实现离线多主合并、不增加全局分布式锁、不管理外部 Agent 进程。需要多端消息唤起时由用户已有 Bot 平台负责，AEL 只提供查询/通知和领取接口。
