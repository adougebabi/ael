# AEL V2 · Agent 主导执行的架构修订包

**当前实施位置：V2-12。不是重建项目，不从 V2-00 开始。**

本包根据用户最新明确的边界修订原任务：Oracle 上用 Docker 部署 AEL Server + Dashboard；Mac / 云电脑上的现有 Agent 用 AEL CLI / 轻量通信脚本领取工作、读取规范、上报进展、上传证据和提交结果。Agent 自行决定、组织并执行编码、编译、测试和浏览器检查。AEL 不启动/监督 Agent，不接管其本机进程树，不强制本地 Docker。

## 使用方式

1. 将本目录放到现有仓库的 `docs/v2-agent-driven-revision/`，不要覆盖原 `docs/v2-execution/` 整个目录。
2. 本包**不包含 WORKLOG、既有回执或数据库**，避免把已经完成的进度重置。
3. 将 `IMPLEMENT-NOW.md` 作为本次 Codex 实施指令。先读本包的架构裁定、24 项影响表和恢复说明。
4. 本地 Codex 核对实际源码与旧任务，追加一条范围修订；再将本包 `tasks/V2-12.md`—`V2-23.md` 的修订内容按实际文件路径纳入原任务说明。保留差异与历史，不改旧证据。
5. V2-00—11 按实际 WORKLOG 保留现有状态；只在 V2-12 内完成受此次边界变化影响的必要修正与回归。不把之前的 DONE 当作新契约已经复验，也不把它们全部重新打开。
6. 当前唯一进行项仍为 V2-12。按修订内容验收后暂停；**本次不开始 V2-13**。

## 优先级

本包在“由谁启动执行、谁负责本机安全与进程管理、客户端 Docker 是否强制”的冲突点上，替代：

- 原执行契约中的远程托管执行要求；
- 原 V2-12 / V2-13 等涉及 Runner 启动和停止 Agent 的要求；
- `AEL-V2-12-Bounded-Closure-Prompt.md` 中仍然保留的可信托管 Runner 要求；
- “客户端一次性 Docker 任务容器为必需后端”的建议。

其余身份认证、权限、候选版本、有效证据、幂等、父子任务、旧数据保护、默认可读 CLI、串行实施要求继续有效。

## 包内材料

- `00-ARCHITECTURE-DECISION.md`：唯一的新责任边界与 Loop 定义。
- `01-ALL-TASKS-IMPACT.md`：V2-00—23 逐项处理方式。
- `02-RESUME-AT-V2-12.md`：从当前阻塞现场恢复，避免返工与另一轮安全研究。
- `03-REQUIREMENTS-TEST-REMAP.md`：旧阻塞/旧测试怎样保留和重新归属。
- `tasks/V2-12.md`—`V2-23.md`：后续任务修订正文，顺序和编号不变。
- `IMPLEMENT-NOW.md`：当前可直接下发的实施 Prompt。
- `PACKAGE-CHECK.md` / `MANIFEST.json`：文档包完整性核验，不是产品测试报告。

本包根据原任务包与用户粘贴的阻塞报告编制，没有读取用户本地未提交源码、执行现场日志或 Oracle。实际实现与回归由本地执行者核对。
