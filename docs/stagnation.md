# 无进展提示与重复失败恢复

`task show`、`next`、任务树和本地工作台区分最近联系、当前阶段、最近有证据的进展和等待接手。心跳只续租，不代表成果；相同产物内容、重复日志或同一候选上相同的检查结论不会刷新证据进展时间。中途进展如需登记真实交付物，需在 `progress.json` 中明确提供 `evidence_kind: "deliverable"` 和可读取的 `artifacts`；未分类或 `diagnostic` 内容仍被记录，但不当作新成果。`.log` 文件本身也不刷新计时；真实检查的新结论可刷新。尚无证据时从任务创建时间计算提示。

项目政策可设置 `no_progress_seconds`；不设置或设置 `0` 使用建议值 1800 秒，正数为自定义提示间隔。它是提醒，不是执行超时，也不改变候选或验收门禁。`max_retries` 可按既有项目政策或任务定义调整，默认建议 3。长工作可在 `progress.json` 中同时提供 `stage` 和未来的 `expected_until`（RFC 3339）；它们展示当前声明，不伪造新的证据进展。命令检查使用自身的 `timeout_seconds`，运行时自动记录阶段和期限；超时保留日志与恢复点。

失败签名绑定执行单元及可选的稳定 `failure_class`，不会因标题、Agent 会话或摘要措辞变化自动清零。未分类失败保守归入该单元的既有预算；确有不同问题时，在失败结果中同时填写不同的 `failure_class` 和实际失败 `artifacts`，系统仅在证据内容未见过时另记类别，原计数继续保留。类别是执行者的明确声明，不能单靠任意新文件或改写措辞证明问题不同。达到阈值后保留单元、输入指纹、尝试与恢复条件并暂停，先做限定根因复核。并行检查各自达到阈值时逐一复核，不覆盖尚未处理的单元。记录复核需要真实可读取的证据引用，并写明已尝试、排除项、假设、下一动作及解除条件，例如：

```json
{
  "actor": "reviewer",
  "tried": "核对三次失败的输入与日志",
  "excluded": "排除文件缺失",
  "hypothesis": "检查配置与输入不一致",
  "next": "核对配置后重试必要检查",
  "recovery": "配置和旧进程状态已核实",
  "evidence": ["runtime:artifacts/review.txt"]
}
```

将以上实际复核写入 `review.json` 后执行：

```sh
./ael task review-failure --task ID --file review.json --json
./ael resume --task ID --json
```

复核不清除失败次数，也不替代必要检查。复核后同一单元再次失败会停止并保留现场；再次复核需要新的真实证据内容，单改文字不能绕过。相同单元取得新的有证据成功结论后才结束该失败周期。定义或标题变更、重启执行者不会自动释放该保护。

失联或超时不证明旧写进程已经停止；涉及旧运行或中断进程时仍须实际核实，并使用 `resume --ack-stopped`，后端会拒绝仍存活的 owner 或进程组。恢复保留当前责任节点与仍有效的检查；候选或输入变化须回到相应早期节点并按现有版本保护复验。父任务继续显示受阻叶子，显式授权的其他独立工作仍遵守既有资源和执行安全约束。
