# 本地任务树

Epic 是类型为 `epic` 的父任务；普通任务仍是叶子，已有任务无需转换。Epic 保留范围、目标与验收要求，当前只汇总子任务，不领取普通实现步骤，也不会因为子任务完成而自动完成整体验收。

创建叶子时设置 `parent` 为当前项目中已存在的 Epic ID，会建立必需成员关系。也可创建普通叶子后显式关联：

```sh
./ael task link --parent EPIC_ID --task LEAF_ID --milestone 阶段一 --json
./ael task link --parent EPIC_ID --task OPTIONAL_ID --required=false --milestone 阶段二 --json
./ael task tree --task EPIC_ID --json
./ael task progress --task EPIC_ID
./ael task integrate --task EPIC_ID --json
./ael verify --task EPIC_ID --check INTEGRATION_CHECK --executor CHECKER --json
./ael task list --parent EPIC_ID --json
```

关联是项目本地的；一个叶子只能有一个显式 Epic 关系，Epic 不能作为叶子。重复关联、自关联、缺失目标以及链接正在执行的叶子会被拒绝。取消必需叶子会保留该成员及取消状态，不能满足父范围；已关联的叶子不能直接删除。关联已完成叶子保留其定义、结果和完成时间。

树结果包含父 `root`、`children`、`required`、`required_completed` 与 `summary`；每个子项携带 `required`、`milestone`、实际 `task` 状态和只读 `summary`。`task progress` 默认显示简要汇总和最近事实，`--json` 使用与树和本机看板相同的投影；单独的 `progress` 命令仍用于记录某个已领取工作单元的事实。汇总分别统计已实施、必要检查通过（已验收）、真实交付回执、未开始、部分检查通过、失败、阻塞、等待接手和取消的叶子；这些状态可以重叠，不是项目完成百分比。取消必要叶子不会减少必需分母；范围变化、取消原因以及实际进展从已有事件读取。完成状态是叶子自身的结果，并不代表父级已经集成或发布。跨工作区导入的历史完成记录保留原时间，但不作为当前工作区已复验的必需完成数。

HTTP 接口使用现有本地 session 鉴权：`GET /api/task-tree?id=EPIC_ID` 与 CLI 使用同一树投影；`POST /api/task-link` 接收 `{ "parent": "EPIC_ID", "task": "LEAF_ID", "required": true, "milestone": "阶段一" }`，省略 `required` 时为必需。任务列表支持 `GET /api/tasks?compact=1&parent=EPIC_ID`。旧版宽松 `parent` 字符串不会在打开旧库时被自动提升为新的显式关联；仍可读取原记录。显式关联旧叶子时保留原定义中的历史父引用，界面以新 Epic 关联为准。较旧的记录或完整备份若会覆盖现有 Epic 关联，将以 `TASK_MEMBERSHIP_CONFLICT` 拒绝，需先核对两份数据。

## 父级集成与整体验收

父任务定义需配置必需检查，`covers` 必须覆盖全部父验收条件。`task integrate` 不运行检查或宣布完成：它先核对必需叶子的当前验收，再将叶子执行期间实际新增、修改、删除的文件内容与当前父工作区逐项比较，记录父候选和被核对的叶子；随后必须对该候选运行父级检查。相同候选可直接对应；早期记录没有可核验内容证明且候选不同、内容被改写、产物被排除或范围不明时，会明确拒绝并要求针对相关叶子核实，而不是编造纳入。此内容核对不声称 Git 合并或远程仓库身份。

父集成检查可在定义中声明 `affected_tasks`，用于将失败链接到已关联叶子的排查范围；声明本身不证明根因。默认影响未知，父候选相对叶子受验内容的差异会要求保守复验；同一文件后续变更时也必须复验受影响叶子的必需检查。后一叶子改写前一叶子的行时，若后一叶子记录的受验输入正是前一叶子的结果、且改写链终点即当前父内容，系统认定前一叶子已纳入并转为复验；输入不衔接（例如并行叶子覆盖、手工回退）仍拒绝。已完成叶子不重新打开。复验在父候选上运行：父定义中配置相同方法、命令和产物要求的必需检查，并在该检查的 `affected_tasks` 标出对应叶子；原叶子的证据和完成时间不变。若有完整影响分析，可在父定义中设置 `integration_impact: {"complete": true, "evidence": ".ael/integration-evidence/impact.md"}`，该非空依据必须存在且纳入父候选，每项必需父检查均须声明受影响叶子；系统记录依据及哈希，不把声明本身当作检查通过。

父候选记录项目 ID、Git HEAD、本地仓库标识、AEL 工具构建和内容清单哈希；非 Git 工作区明确标为本地内容证明，不声称仓库或提交身份。本地不同仓库不会仅凭目录名或 URL 自动视为同一仓库；叶子提交不是父提交祖先时，需在父候选上复验该叶子必需检查。同文件重叠变更只在可用 Git 原始内容核验原有变更仍保留时接受，未知、未提交或非文本重叠不能靠弱检查冒充纳入。若可选叶子的内容用于解释必要叶子与父候选之间的差异，该可选依据也会被记录并在关闭前复核。父候选或必要范围变化后需重新准备并验证；已完成叶子的候选、证据和完成时间不会因此重写。`verified` 在必需父检查通过后完成；`released` / `merged` 仍需针对相同候选的明确确认和真实交付回执。`report` 可交付带失败发现的报告，但不等同于产品验收通过。

父检查必须在准备父候选时使用的工作区运行。同一 AEL 运行库内，父检查与其他重叠工作并行，或多个父检查共用可写工作区并行时，即使文件后来被还原，也不能证明检查期间候选始终不变：检查结论保留为历史，工作停止后需要重新准备父候选并逐项复验。父级推进还会等待未确认停止的重叠工作和候选文件待写操作；租约到期本身不证明旧进程停止。旧版本已完成任务若仍有遗留执行，核实进程停止后可对该任务执行 `resume --ack-stopped` 清理遗留接手，原完成时间和结果保持不变。若交付回执已保存但父级等待工作区，工作结束且候选未变时用 `resume --ack-stopped` 继续，复用已有回执；候选改变时先核对旧交付的实际结果，再对新候选重新验收。

上述协调只覆盖向**同一运行库**声明工作区、遵守领取和停止规则的 AEL 工作。独立运行库、直接编辑器或不遵守协议的进程不受该协调约束；需要对集成检查使用隔离、稳定的工作区，不能将结束时指纹相同当作外部写者整个检查期间未改动的证明。

可在全新隔离目录运行以下演示。它只使用确定性的测试执行器，不运行真实 Agent：

```sh
python3 scripts/epic_tree_demo.py --bundle /path/to/unpacked-distribution --out /tmp/ael-epic-fixture
```

演示创建父任务与三个独立验收的叶子，对照 CLI 与本机 HTTP 树，并停止自己启动的 Dashboard。`--out` 必须为新目录或空目录。
