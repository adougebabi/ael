# V2-12 · 远程 Runner 的真实单任务闭环

**前置：** V2-11 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 代码仍在执行者机器修改，中心服务真实接收领取、进度、验证与结果。

## 实施内容

1. Runner 主动连接并登记能力、运行版本、已授权项目/工作区；pull 指定工作，取得租约与 fencing token。服务端不反向 SSH 到个人电脑。
2. 复用现有命令/Codex 适配，在本地执行当前 Attempt，读取核对过的上下文；stdout 不是通过证明。结果与已 finalized 证据提交到 Server。
3. 命令仅在可信项目/明确授权中执行；远程扫描 Bot 不可自行把任意任务内容当 shell 或扩大到发布。
4. 开发、命令检查、场景/模型审查分别保留来源；人工任务进入等待，不伪装成无命令就通过。
5. Runner 自动消费下一动作，完成当前叶子后按父计划继续；一个外层监督循环，禁止子 Agent 递归启动 loop。

## 必须通过的本项验收

- [ ] 独立 fixture 上真实进程完成“修改文件 → 命令验证失败 → 修复 → 验证通过”，Server 接收证据与结果。
- [ ] 进程退出 0 但缺最终结果/必需证据，不能完成任务。
- [ ] 无授权的工作区/发布命令不执行；Server 上没有启动项目命令。
- [ ] 有已登录 Codex 时执行隔离 smoke；缺少条件要明确记录，不能把 fixture executor 称为真实 Codex。
- [ ] 旧本地 Managed/Attached 流程无新增回归。

## 边界

测试用 fixture executor 只证明程序协议；真实 Agent 验收放入最终外部验收清单，不伪造。
