# V2-09 · 远程任务与 CLI：唯一权威的第一条路径

**前置：** V2-08 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 两套客户端能够在同一个 Server 创建、读取和更新任务，不再同步两份本地数据库。

## 实施内容

1. 支持显式 server profile / project connect；凭据位于仓库外，项目只存非敏感绑定标识。Remote/Local 模式可见且互斥，不在断网时静默回退。
2. 任务、父子关系、计划、查询和允许的状态操作经统一 API 调用领域服务。Server 是远程任务定义/运行态权威；本地 records/outcomes 导入路径必须在 Remote 禁用。
3. 为变更加入 expected revision、幂等键、操作 ID；过期编辑返回可理解的冲突，重复提交返回既有结果。
4. 客户端不会将自己的绝对目录要求 Server 打开；本地路径只在客户端解析。服务端配置访问范围不依赖客户端声明可信度。
5. CLI text / --json 两种输出均支持 Remote；缓存显示时间与失联状态，不能离线伪装完成。

## 必须通过的本项验收

- [ ] 客户端 A 创建父子任务，独立配置目录的 B 立即读到，同一 ID 不依赖 Git push/pull。
- [ ] 两个客户端编辑同一修订，一方冲突；同一幂等请求重放不重复创建。
- [ ] 撤销 Token 后写入失败；跨项目读取失败。
- [ ] 断网不能在本地另创同名权威任务，恢复后读取服务端结果。
- [ ] 两客户端无共享运行库，所有状态通过真实 HTTP 验证。
