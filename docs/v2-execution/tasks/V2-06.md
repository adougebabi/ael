# V2-06 · 停滞检测、重复失败与可恢复停止

**前置：** V2-05 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 把无执行者、健康长任务和真实无效循环区别开，阻止重复消耗。

## 实施内容

1. 记录最近联系时间、执行阶段、最近有证据的进展、候选与失败签名；心跳、重复日志和重复提交不算新成果。
2. 增加可配置无进展提示和同类失败阈值；默认值作为可调建议。测试使用可控时钟，不实际等 30 分钟。健康长测试可提供阶段与运行期限，不因没有 commit 被直接终止。
3. 同一问题重复失败时先进入限定根因复核；仍不收敛保存现场并停止该单元。改标题、重启 Agent 或无关修订不能自动清零预算。
4. 暂停与恢复原因必须含当前单元、失败输入、已尝试、解除条件和下一动作；恢复只重做必要检查。不得通过放松门禁解决无进展。
5. 把提示、暂停结果与恢复操作接到 CLI 和父/子详情；任务调度可继续处理显式授权的其他独立任务，但不能掩盖被阻塞项。

## 必须通过的本项验收

- [ ] 重复 3 次同类失败触发根因复核/停止，而不是无限执行。
- [ ] 只发 heartbeat 不清除无进展提示；有真实检查新结论则更新进展。
- [ ] 健康的长测试不被误当空转，超时后保留日志与恢复点。
- [ ] 失联但旧写进程未确认停止，不能把超时直接当成安全抢占。
- [ ] 恢复后候选/输入变化准确失效对应证据，历史失败仍可查看。
