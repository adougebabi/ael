# V2-13 · 双执行者协作、断网与恢复

**前置：** V2-12 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 本地开发和云电脑验收能可靠交接，避免双写、丢提交或离线伪成功。

## 实施内容

1. 两个独立 Runner 从同一服务领取任务，原子去重；项目/父级并发上限与能力匹配可配置，默认每个开发 Runner WIP=1。
2. 对独立分支/工作区执行开发；验收使用稳定候选。代码合并由既有 Git/授权流程处理，不让中心任务同步冒充代码同步。
3. 网络失败使用有界重试与持久化待提交队列；同一操作重试保持幂等键。旧结果不能在重连后套用新任务修订。
4. 租约丢失后 Managed 停止自己管理的写进程并保存现场；Attached 无权杀宿主时记录失联，拒绝过期结果，不启动同工作区第二写入者。
5. 服务重启、Runner 退出、发布回执丢失都需先查询既有状态；不能保证 exactly-once，也不盲目重放副作用。

## 必须通过的本项验收

- [ ] 两个隔离客户端同时 claim 同一单元只有一个成功；不同无冲突单元可并行。
- [ ] 服务已接受提交但响应丢失：重试不生成第二个结果/后继任务。
- [ ] 断网租约过期后提交拒绝；重连查看失败原因与恢复位置。
- [ ] 两条分支的 UI 结果不会串用，候选变化使旧证据明确过期。
- [ ] 服务端只用自己的 SQLite，本机容器测试使用实际 HTTP，不共享数据库文件。

## 边界

不做离线多主合并，不做复杂全局分布式锁服务。
