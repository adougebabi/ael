# V2-02 · 父任务与叶子任务：最小可用任务树

**前置：** V2-01 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 一个大任务真正拥有可独立执行和验收的子任务，而不是正文里的清单。

## 实施内容

1. 复用现有 Definition.Parent / Dependencies，增加明确的聚合类型与必要元数据；普通旧任务无需迁移成 Epic。父任务不是默认可无限写代码的大执行单元。
2. 支持创建父任务、添加/关联已有叶子任务、查看任务树；父范围、交付目标、必需/可选标记和里程碑分组可保存。里程碑只分组，不引入第三套状态机。
3. 约束无父子循环、无跨项目误关联、无重复成员；依赖与父子关系分开。删除/取消必要子任务不能静默减少父范围。
4. 父结果汇总基于叶子的真实状态，不按文件存在或子任务自述完成。先提供可用的 CLI/API 树结果及现有列表的父子入口，详细 Epic 页留到 V2-05。
5. 对本地存储做兼容增量升级，在隔离旧库上验证；已完成历史记录及原时间保留。

## 必须通过的本项验收

- [ ] 创建 1 父 + 3 子，子任务沿原有流程独立完成；父树显示真实状态，父不能提前完成。
- [ ] 重复关联、循环、取消必要子任务、旧普通任务读取均有测试。
- [ ] CLI 和 API 指向同一树；重新启动后关系不丢失。
- [ ] 提供一条可执行演示脚本，在 fixture 上产生任务树，不仅是结构体单测。

## 边界

不做自动拆分、不做调度器、不启动云服务；本项交付的是可用任务树。
