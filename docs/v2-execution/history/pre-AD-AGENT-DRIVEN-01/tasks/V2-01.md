# V2-01 · CLI 默认可读，JSON 显式选择

**前置：** V2-00 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 用户直接执行命令能够读懂状态；已有 Agent 与脚本仍有稳定机器接口。

## 实施内容

1. 在单一输出层支持默认 text、显式 --json、--verbose 和无色输出。优先覆盖全部现有命令，不只 task show；长正文、流式日志与一次性 JSON 的边界清楚。
2. 任务输出直接显示标题、父任务、当前责任、执行者、实际成果、必要检查和下一动作；错误显示原因、恢复建议、短错误码。stdout 与 stderr 分工清楚。
3. JSON 模式保持现有结构兼容，并给新增协议清楚版本；不得混进 ANSI、spinner 或自然语言提示。TTY 与管道测试，中文对齐不截断关键 ID。
4. 检查 cmd 参数解析对布尔 --json 的支持，不能吞掉后续子命令或位置参数。更新内部 probe/version 解析、打包/升级脚本、Skill 和所有自动化调用为显式机器格式。
5. 定义退出码兼容规则：命令执行成功不代表任务已完成。等待/阻塞要显示明确状态；执行错误和检查失败的脚本语义必须有测试，不能悄悄破坏旧自动化。

## 必须通过的本项验收

- [ ] 实际二进制执行 help、version、doctor、task list/show、非法命令和阻塞任务，可读且无原始对象倾倒。
- [ ] 相同请求 text 与 JSON 表达同一领域结果；JSON 可解析、管道无颜色。
- [ ] 已有测试驱动器、升级 probe、Managed 结果解析正常；没有依赖旧默认 JSON 的漏改入口。
- [ ] 在未初始化的隔离目录读取帮助/版本，不会隐式初始化该目录。
