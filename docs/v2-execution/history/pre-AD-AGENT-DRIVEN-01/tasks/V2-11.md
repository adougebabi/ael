# V2-11 · 跨设备候选、规范快照与执行上下文

**前置：** V2-10 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 云端能知道 Agent 实际检查了哪个版本，并让另一设备获取同一份规范依据。

## 实施内容

1. 区分 project/repository/checkout/workspace/runner 身份；项目绑定需明确选择，不能凭目录名自动合并。
2. 客户端基于 commit/内容清单/必要未提交差异生成可移植候选。跨平台稳定的身份不依赖绝对路径、mtime 或 PID；差异不明时不宣称等价。
3. 规范仍以仓库版本为权威。上传所用内容快照、来源、哈希、状态与适用理由；服务端索引只读快照，不编辑第二份现行正文。历史/候选规范与生效基线分开。
4. 任务/检查上下文从服务端版本与 Runner 本地实际工作区共同核对；范围扩大补充必要依据；密钥、整机历史和无关源码不能默认全量上传。
5. 本地文件变化使提交失配时给出受影响范围，不简单全部重置；证据复用只在受检输入及配置等价可证明时允许。

## 必须通过的本项验收

- [ ] 相同 commit 的两个路径/机器身份不同但候选可对齐；相同分支不同 commit 不能复用检查。
- [ ] Agent 取到的规范与 Dashboard 阅读的快照一致，来源版本可追溯。
- [ ] 未提交业务变化被检测；任务日志/上传产物不会无意义改变代码候选。
- [ ] 不明引用、基线冲突和缺失规范能够阻断相关工作并说明原因。
- [ ] 既有 Local 索引与 Context 用例仍通过。

## 边界

不在服务器做隐式 Git checkout/执行 hooks；不把所有历史文档强制升级成当前契约。
