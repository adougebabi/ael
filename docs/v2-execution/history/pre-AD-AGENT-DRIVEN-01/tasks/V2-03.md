# V2-03 · 拆分计划：复用用户分项与 Agent 辅助补全

**前置：** V2-02 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 把大范围要求变成有边界、有依赖、有验收覆盖的叶子任务，且可幂等应用。

## 实施内容

1. 规划输入支持整段要求、已有分项和已存在任务 ID。用户已有分项优先映射，保留原标识和含义；相同计划重试不能重复生成子任务。
2. 定义轻量 PlanProposal：子任务目标、非目标、产物、验收、依据、依赖、顺序、能力要求；父验收项映射到子任务或集成检查。Task 类型与检查方法按实际范围选择。
3. 检查缺失覆盖、循环依赖、重复职责和无法独立验收的切分。共享 API/迁移等前置显式列出；单纯按文件/技术层拆分不能代替可交付单元。
4. 更新产品 Skill：已有授权范围内可读取需求、提出并应用无冲突拆分；关键范围变化或未明确的产品决定才进入确认。程序校验结构，Agent 负责语义，不能靠关键词假装理解任务。
5. 提供计划预览/差异/应用命令和简明可审阅结果。已有子任务保留执行历史；重规划只修订受影响项，不清空已验收产物。

## 必须通过的本项验收

- [ ] 未拆大任务产生完整 PlanProposal；有既有分项的输入不重复造任务。
- [ ] 父验收有缺口时不能宣布规划完成；缺口精确定位。
- [ ] 重复应用幂等，已有完成子任务不会重置；无效依赖拒绝。
- [ ] 后端 Bug 不产生 UX 检查；只验收任务不获得业务修改权限。
- [ ] 在有可用宿主时演练一次真实规划；若仅做确定性规划夹具，明确其验证边界，不声称完成真实模型能力验证。

## 边界

不按未取得的 MeroMero 任务全文臆造分解；不把所有计划无差别送人工审批。

## 结束动作

完成所有必需验收 → 生成 `../receipts/V2-03.md` → 保存本地 Git/补丁检查点 → 更新 WORKLOG 为 DONE → 运行账本检查器。
无需再次请求“继续”；在既有授权范围内直接进入 V2-04。存在真实阻塞则只保留本项 BLOCKED，不开后续任务。
