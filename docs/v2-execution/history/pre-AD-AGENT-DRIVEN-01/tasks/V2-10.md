# V2-10 · 中心证据存储与授权上传下载

**前置：** V2-09 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 一台机器产生的截图/报告可以由另一台机器和同一 Dashboard 读取。

## 实施内容

1. 实现附件上传、finalize、获取元数据、受控下载。先写临时文件再校验大小/哈希并原子落盘，只有 finalized 工件能成为验收证据。
2. 元数据记录 project/task/attempt、候选、MIME、长度、哈希、来源和时间；文件存数据库外。同项目可做内容寻址去重，但不通过哈希泄露跨项目文件是否存在。
3. 设置项目配额、单文件大小与类型限制；路径规范化、symlink/穿越防护、未完成上传清理、下载权限均测试。SVG/HTML 等主动内容不原样作为同源可执行页面。
4. CLI 上传本地文件得到稳定 artifact ID；服务端响应不得要求其他电脑读取本机路径。提供报告/图片预览的最小可用入口和内容错误反馈。
5. 证据清理保留引用与“原件已清理”的状态；活动任务和待审阅依赖默认不删，删除前 dry-run。

## 必须通过的本项验收

- [ ] A 上传真实 PNG 和报告，B 登录后读取相同字节/哈希；未授权读取失败。
- [ ] 上传中断不会出现有效验收证据；重复 finalize 幂等。
- [ ] 越界路径、伪造 MIME、超额、恶意文件名被拒绝。
- [ ] 删除本地原文件后，服务端证据仍可访问；清理服务端原件后 UI 不显示假预览。
- [ ] 数据库未保存大 BLOB，容量统计包含临时上传及附件。

## 边界

无需 S3/MinIO；首版不做视频转码服务，可直接安全存储与读取支持的录屏类型。
