**目标：** 扫描结果成为可定位、可判断、可关联修复的发现，而不是长篇报告。

## 实施内容

1. 定义 Finding：关联检查/任务/候选、规则或验收项、路由与稳定定位、期望/实际、复现步骤、影响、来源、证据；UI 需截图，UX 需交互步骤/trace。
2. 严重性和模型判断是建议，不自动变成已确认缺陷。必要证据不足标待补证/无法验证，不使用自信分代替事实。
3. 去重依据明确的页面/规则/定位/候选关系；连续扫描保留出现记录，不每次造新 Bug，不跨不同问题强行合并。
4. 问题列表支持筛选、查看截图位置、关联任务；不要求人工复制 Markdown 里的每条问题。
5. 扫描报告交付与被扫对象通过分开；只验收任务可报告失败，但不能因此完成产品验收。
