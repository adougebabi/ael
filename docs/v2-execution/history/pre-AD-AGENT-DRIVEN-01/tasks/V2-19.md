# V2-19 · CLI 与项目资产的轻量升级

**前置：** V2-18 已 DONE，且其回执存在。
**执行纪律：** 先读 `../00-EXECUTION-CONTRACT.md` 与 `../WORKLOG.md`，只实现本项；本项 DONE 后才读取下一任务正文。
**目标：** 升级一次本机工具即可使用兼容远程服务，不逐项目搬四个平台包。

## 实施内容

1. 实现面向用户的版本检查/upgrade/明确版本选择与 dry-run，复用受管文件保护。按当前平台下载、校验、临时安装、原子切换、保留回退点。
2. 本机 CLI/Runner、项目 Skill/入口、Server 版本分别识别；兼容更新不改全部项目配置。协议不兼容明确阻止相应动作，旧兼容版本仍能访问。
3. Remote 项目采用轻量入口/协议要求，二进制放机器级版本缓存；现有项目自带工具链只在显式迁移时改变，不删除用户旧文件。
4. Skill 更新采用受管内容检测与用户修改冲突提示；活动 Agent 固定本次协议/工具版本，不在执行中热换核心。
5. 升级入口输出可读步骤/结果，JSON 供自动化；新版无发行源、网络失败、权限不足均有清楚恢复信息。

## 必须通过的本项验收

- [ ] 本地发行 fixture 从旧版本升级新版本，篡改包/下载中断/权限失败保留旧可执行文件。
- [ ] 两个项目使用同一机器缓存，兼容更新不分别重装；旧 local 项目仍可运行。
- [ ] 活动任务不被自动杀死或被偷偷换 Skill；不兼容版本给出精确升级动作。
- [ ] 用户修改的受管文件不覆盖；回滚不覆盖新的业务资料。
- [ ] 既有 bootstrap/probe 测试以 --json 正常运行。

## 边界

正式在线更新可用性依赖授权发布；本项不能把 fixture 下载称作已上线发行。
