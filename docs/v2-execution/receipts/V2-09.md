# V2-09 · 远程任务与 CLI：唯一权威的第一条路径

- 开始基线：本地 `main` 的 `f2d244d`（V2-08 检查点）。`internal/remote/` 和 `cmd/ael/remote.go` 提供仓库外 profile、非敏感项目绑定、远程 CLI 与带时间的离线缓存；`internal/server/remote_*` 将授权的任务、父子树、计划和允许的状态操作接到 Server 自有的项目隔离领域库。
- Server 事务同时保存任务变更、完整状态 revision 和操作回执；相同幂等键与相同请求返回原回执，不同请求冲突。计划使用现有可恢复 journal，操作 ID 和幂等键与计划 ID 绑定；中断可查询、重放或经明确放弃保留部分成果。已提交但文件投影冲突时，操作查询明确显示 `projection_blocked`，不会伪报完整成功。
- 防回退与身份：remote 绑定先于本地运行库打开检查，即使绑定损坏也不导入 checkout 的 records/outcomes。项目模式使用目录锁防止本地初始化与远程连接并发形成双权威；凭据在仓库外且检查私有权限、ACL 和硬链接。Server 对授权变更及任务请求使用跨实例围栏并在取得锁后重新认证，撤销完成后的在途写入被拒绝。HTTP 端按项目角色授权，不使用请求内 executor 字段提升权限。
- 数据：远程项目的数据库和投影只位于 Server 数据目录；客户端只在自己的 checkout 写非敏感 `.ael/remote.json`，不创建本地任务运行库。已有本地项目不会自动切换或导入；本项没有真实开发执行器、外部部署或业务迁移。
