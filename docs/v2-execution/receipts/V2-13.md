## 实现

- CLI 的 runner 写操作与显式 artifact upload 会在网络写入前保存私有操作记录。请求、原责任、候选和上传字节固定，文件校验与文件锁支持 CLI 退出后的恢复。
- `runner retry --pending FILE` 先查原回执并比对服务端请求摘要。未受理时使用原 attempt/token/fence 续租核对，再提交原始请求。每轮最多三次，HTTP 请求超时五秒，重试间隔 100/200 毫秒。预算耗尽保留操作文件并返回恢复入口。
- `runner recover --runner RECEIVER --file FILE` 明确确认旧执行者停工，或声明独立工作区。服务端撤销旧接口责任，持久记录未知工作区及接收方领取约束。完成实施后，可把同一候选交给另一身份验收，历史实施 PASS 保留，接收方重新报告必需检查。
- 活动远程任务可以取消。取消后旧责任继续以 interrupted/unknown 保留，旧提交失效，明确停工确认可释放责任。runner show 提供 last_reported/lost 和 host_execution_state=unknown。
- 复用 Store.Write、p.mutate、RemoteClaimTx、RemoteAttemptTx、SubmitRemote、原附件 start/chunk/finalize、服务端回执、规范上下文与状态机。原 Local 入口继续按其既有规则执行。

代码位于 cmd/ael/remote_agent_operation.go、remote_agent_upload.go、internal/core/remote_runner.go、internal/server/remote_recovery.go。CLI 帮助、分发 Skill、README 和设计说明已同步。

## 修复与兼容

独立核验发现并修正了以下边界，固定验收已包含对应负例。

1. finalized 上传必须通过原 start 请求的完整幂等校验。相同字节但 task/candidate/source/operation 不同仍拒绝。
2. 普通操作回执增加服务端从原始规范化 JSON 计算的 request_digest。查询核对完整原请求，避免另一 checkout 同键同操作 ID 的不同请求误认旧回执。旧回执缺字段时，经原接口原键重放完成原有完整幂等校验。
3. 历史 completed execute 交接前检查当前是否已有活跃责任，避免改写正在执行的验收目标。
4. 候选首次捕获的结构体与磁盘读回的对象统一使用 RequestDigest 计算摘要。离线 observe 期间修改本地文件，恢复仍使用首次固定候选。
5. 尚未领取的交接可在当前版本下显式改派，原接收方不能静默领取，活跃责任仍要求针对当前 Attempt 恢复。
6. cancelled 任务的停工确认保留终态并清理旧责任。首次夹具在取消后直接尝试新责任，被 RUNNER_WIP 拒绝，原失败日志保留。

数据库增加 remote_workspace_holds、remote_submission_digests 两张表，采用 CREATE TABLE IF NOT EXISTS。原任务与回执保留。新版字段为响应的附加信息。升级前数据没有新摘要的回执继续可查询和按原接口校验重放。二进制降级后的新工作区约束兼容性未作为本项验收。
