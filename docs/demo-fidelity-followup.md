## 0.1.12：按用户对照图修正模块及接手恢复

用户指出差异不只是拥挤，而是任务详情的模块、顺序和展示方式本身不同。本次重新参照 Demo 的 `taskOverview`、`taskChecks`、`taskExecution`、`taskBasis` 和人工验收模板调整：

| 位置 | 本次实现 | 数据和边界 |
| --- | --- | --- |
| 概览 | 状态提示、目标与范围、全宽验收概况、全宽最近进展依次呈现 | 目标、范围、检查数和工作进展来自任务定义、当前检查和实际 Attempt |
| 检查与验收 | 候选与修订提示、带通过数的检查面板、检查行、后续说明卡 | 继续使用 `current_checks`、`current_runs`、`check_access` 和服务端门禁；不修改非人工检查的方法 |
| 执行过程 | 工作进展时间线优先，执行计划和原始事件收进技术记录；旧 `section=technical` 链接仍可打开 | 仅展示实际 Attempt、执行者、结果、时间和产物 |
| 规范与决策 | 顶部依据说明和统一列表面板；保留准确版本阅读与来源入口 | 区分实际提供、显式引用及待核实资料，不填入 Demo 样本 |
| 工作台与人工验收 | 符合后端条件的任务行可直接进入人工验收；弹窗采用固定头尾和滚动正文，提供按结果变化的说明及真实状态回执 | 保留候选、修订、证据和检查资格校验；补充证据仍是已有真实引用，未实现浏览器上传 |
| 领取和结果提交 | 在当前浏览器标签页保存实际收到的领取凭据和草稿；重新核对同一 Attempt、租约、责任和修订；结果不明时原样重试 | 不从执行者名称或任务查询结果自动取得凭据；旧凭据已丢失时需用户确认全部旧执行停止后恢复 |
